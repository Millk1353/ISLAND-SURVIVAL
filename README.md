# ISLAND SURVIVAL V15 — Multiplayer Online

تطوير مباشر على لعبة ISLAND SURVIVAL الموجودة (لم يتم إعادة بنائها من الصفر):
- ✅ إصلاح جاذبية الحيوانات والكائنات (فيزياء حقيقية مع تصادم البلوكات).
- ✅ نظام أبواب حقيقي (فتح/إغلاق، منع المرور، مزامنة، حفظ).
- ✅ Multiplayer Online حقيقي عبر WebSocket + Node.js (بدون مكتبات خارجية).
- ✅ 3 سيرفرات/عوالم مستقلة فعليًا على نفس الخادم.
- ✅ اللعب الفردي (Offline) يعمل كما قبل دون أي تأثير.

## 1) بنية المشروع

```
island-survival-multiplayer/
├── public/
│   └── index.html          ← ملف اللعبة المطوَّر (الواجهة + منطق العميل)
├── server/
│   └── server.js           ← خادم Node.js (HTTP + WebSocket يدوي RFC6455)
├── data/                   ← يُنشأ تلقائيًا: حفظ العوالم واللاعبين (JSON)
├── package.json
└── README.md
```

## 2) التشغيل محليًا

المتطلبات: Node.js 18 أو أحدث.

```bash
cd island-survival-multiplayer
npm start
# أو مباشرة:
node server/server.js
```

الافتراضي: `http://localhost:8080` (يخدم اللعبة) و WebSocket على `/ws`.

- غيّر المنفذ: `PORT=9000 npm start`
- غيّر الحد الأقصى للاعبين لكل عالم: `MAX_PLAYERS=50 npm start`

ثم افتح اللعبة من جهازك أو أي جهاز على نفس الشبكة:
- من نفس الجهاز: `http://localhost:8080`
- من جهاز آخر بنفس الشبكة: `http://<IP-الجهاز>:8080`

## 3) ربط العميل بعنوان الخادم

داخل اللعبة (شاشة البداية ← 🌐 السيرفرات):
- حقل «عنوان الخادم» يقبل `ws://` أو `wss://`.
- يُحفظ العنوان تلقائيًا في LocalStorage (المفتاح `mp_server_url`).
- نفس الحقل موجود في ⚙ الإعدادات داخل اللعبة.

العنوان الافتراضي عند فتح اللعبة من الخادم نفسه محسوب تلقائيًا من hostname.

## 4) السيرفرات الثلاثة (عوالم مستقلة فعليًا)

| المعرف | الاسم | النوع | البذرة | المميزات |
|---|---|---|---|---|
| `island` | Island Survival | جزيرة متنوعة | 13337 | بقاء عادي: موارد وتطوير وبناء واستكشاف |
| `adventure` | Adventure World | ممالك الكهوف | 90424 | مغامرات: كهوف وموارد ووحوش وتعاون |
| `creative` | Creative World | جزيرة متنوعة | 777777 | بناء: kit موارد بناء عند الدخول |

كل عالم له: بذرة مستقلة، تعديلات بلوكات مستقلة، حالة أبواب مستقلة، ساعة مستقلة،
وحفظ مستقل للاعبين (`data/worlds.json` + `data/players.json`).

## 5) البنية الخلفية والحماية

- **Server Authoritative** للعناصر الحرجة: تعديلات البلوكات، حالة الأبواب، وقت العالم،
  قائمة اللاعبين، الحد الأقصى لكل عالم، منع تكرار الأسماء (يُضاف `#n`)، حفظ اللاعبين.
- **Rate limiting** لكل نوع رسالة (حالة/بلوكات/أبواب/كائنات) مع طرد عند الإساءة.
- التحقق من صلاحية الإحداثيات والبلوكات في الخادم، وحدود لحجم الرسائل (32KB).
- حركة اللاعبين والكائنات تُمرَّر (relay) مع Interpolation عند باقي اللاعبين.
- WebSocket منفَّذ يدويًا (RFC6455) — لا حاجة لأي `npm install`.

### بروتوكول الرسائل (ملخص)

| الاتجاه | الرسالة | الوصف |
|---|---|---|
| C→S | `join {world,name}` | الدخول لعالم |
| S→C | `welcome {id,world,seed,type,edits,doors,time,kit,inv,players}` | حالة كاملة |
| S→C | `player:join / player:leave` | دخول/خروج |
| C→S | `state {x,y,face,skin,anim}` (10Hz) | حركة اللاعب |
| C→S | `block {x,y,t}` | تعديل بلوك (يتحقق منه الخادم ويبثّه) |
| C→S | `door {x,y,open}` | فتح/إغلاق باب |
| C→S | `mob:spawn / mob:death / mobs[...]` | مزامنة الكائنات |
| C→S | `inv {items,equipment}` | حفظ حقيبة اللاعب على الخادم |
| S→C | `time {day}` | مزامنة الوقت (كل 30 ثانية) |
| ثنائي | `info` / `chat` | حالة السيرفرات / دردشة |

## 6) النشر على استضافة تدعم WebSocket

### خيار أ: VPS (موصى به)

```bash
# على الخادم
git clone <repo> && cd island-survival-multiplayer
npm start            # أو: PORT=8080 pm2 start server/server.js --name island
```

مع Nginx كوكيل عكسي + WSS:

```nginx
server {
  listen 443 ssl;
  server_name your-domain.com;
  ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;
  }
}
```

ثم في اللعبة ضع العنوان: `wss://your-domain.com`

### خيار ب: Render / Railway / Fly.io

- أمر البناء: لا شيء (بدون dependencies).
- أمر التشغيل: `node server/server.js`
- فعّل دعم WebSocket في إعدادات الخدمة (Render وRailway يدعمانه افتراضيًا على نفس المنفذ).
- أضف متغير `PORT` حسب المنصة إن لزم.
- للحصول على WSS استخدم نطاق المنصة `wss://<service>.onrender.com` مباشرة (شهادة HTTPS جاهزة).

## 7) الاختبارات التي أُجريت

شغّلت الخادم فعليًا وأجريت اختبارات تكامل آلية بعملاء WebSocket خام (انظر سجل الاختبار):
دخول لاعبين، ترحيل الحركة، ترحيل تعديلات البلوكات والأبواب، عزل العوالم الثلاثة،
خروج وعودة مع استعادة الحقيبة، حماية من الإغراق (kick)، اكتمال السيرفر، والحفظ على القرص.
كما فُحص نحو كود العميل والخادم بـ `node --check`.

> لم يُختبر تشغيل متصفحين حقيقيين داخل هذه البيئة (لا متصفحات هنا) —
> استخدم قائمة الفحص اليدوية في نهاية الملف عند النشر.

## 8) قائمة فحص يدوية سريعة بعد النشر

1. افتح اللعبة من جهازين مختلفين ← 🌐 السيرفرات ← دخول نفس السيرفر.
2. تأكد أن كل لاعب يرى الآخر واسمه فوق رأسه، وأن 👥 يعرض العدد الصحيح.
3. اكسر/ضع بلوكات من جهاز ← يجب أن تظهر فورًا في الآخر.
4. ضع بابًا وافتحه/أغلقه ← يتزامن ويمنع/يسمح بالمرور.
5. أغلق الاتصال في أحد الجهازين ← تظهر رسالة انقطاع وإعادة اتصال تلقائية.
6. ادخل إلى السيرفرات الثلاثة وتأكد أن العوالم مختلفة ومنفصلة.
